## Diagnosis

There are **two distinct populations of generated 3MFs**, each with a separate root cause:

### Population 1 — EGM-generated files (serials [155]-[166], [1020]-[1060]): FIXED

Generated by `generate_stl_3mf.py` → `trimesh.Scene.export()` → `_inject_bambu_extruder_metadata()` in `gradient_surface_diagnostic.py`.

**Root cause:** Trimesh's raw 3MF export produces only three files:
```
3D/3dmodel.model
_rels/.rels
[Content_Types].xml
```

`_inject_bambu_extruder_metadata()` then adds `Metadata/model_settings.config` with per-object extruder assignments, but **never writes `Metadata/project_settings.config`**.

Bambu Studio's parser checks: *if `model_settings.config` is present, `project_settings.config` must also be present.* When `project_settings.config` is absent, Bambu fires the "invalid config" dialog regardless of whether `model_settings.config` is well-formed.

**Evidence:** Every file in this population has exactly this structure:
```
3D/3dmodel.model
Metadata/model_settings.config
[Content_Types].xml
_rels/.rels
```
No `project_settings.config`. No `slice_info.config`. No thumbnails.

### Population 2 — `[167].3mf` (the single Qidi Studio re-save): NOT fixed, no code change needed

Serial `[167]` was opened by Thomas in **Qidi Studio** (a Qidi fork of Bambu Studio for the X-Plus 4) and saved. This rewrote the entire file with Qidi-specific schemas (`schemas.qiditech.com`), metadata (`QIDIStudio-02.03.01.70`), and printer profiles (`◀ Qidi Plus4 0.4 nozzle ▶`). Bambu Studio (the non-Qidi version) does not recognize these Qidi IDs, triggering the warning.

**This file is a one-off artefact of Thomas editing it in Qidi Studio. No code change needed.** Future regenerations from the EGM source will produce clean files.

### Population 3 — plate_text.py plaque files: Never affected

`plate_text.py` copies the full `plate_template.3mf` (Bambu Lab A1, version `02.05.03.61`) and patches it. These files already contain `project_settings.config`, `slice_info.config`, and thumbnails. The plaque workflow has no issue.

## Fix Approach — Option B (programmatic injection)

Added `project_settings.config` generation to `_inject_bambu_extruder_metadata()` in `gradient_surface_diagnostic.py`.

**Rationale for Option B over Option A (template swap):** The EGM generator does not use a template — it calls `trimesh.Scene.export()` directly. There is no template file to swap. The fix must be in the code that post-processes the trimesh output.

**What the injected config contains:**

```json
{
    "version": "02.05.03.61",
    "printer_model": "Bambu Lab A1",
    "printer_variant": "0.4",
    "printer_settings_id": "Bambu Lab A1 0.4 nozzle",
    "print_settings_id": "0.20mm Standard @BBL A1",
    "default_print_profile": "0.20mm Standard @BBL A1",
    "filament_settings_id": ["Generic PLA @BBL A1", ...],
    "default_filament_profile": ["Generic PLA @BBL A1"],
    "nozzle_diameter": ["0.4"]
}
```

These are the **built-in generic profiles** that ship with every Bambu Studio installation. They are intentionally minimal — Bambu Studio can parse them without error, the dialog disappears, and Thomas reassigns printer/filament/process in the slicer UI as usual (he already does this for each print job).

The `filament_settings_id` list length matches the number of extruder slots in the scene (one entry per object, same as the model_settings extruder mapping).

**Idempotency:** The zip-rewrite loop now skips both `model_settings.config` and `project_settings.config` before writing fresh copies, so calling the function twice does not create duplicate entries.
